# 经验教训 · 20 条

> 全部来自一次真实的「自动修路」工程（Minecraft 1.21.11 / Fabric / Meteor + Baritone / HTTP 桥）。
> 每条都写了：**现象 → 根因 → 做法**。凡是"'报成功'但没生效"的，一律归到第 1 条去理解。

---

## 一、API 与坐标

### 1. 所有动作 API 都会报假成功，只有独立回读可信

```
/place  → {'ok': True, 'msg': 'placed 圆石 at -412,68,272'}   但回读是空气
/hold   → "holding 工作台 (slot 0)"                            但手上还是铁剑
/fill   → "queued 15 cells"                                    一半被静默丢弃
```

**做法**：动作负责执行，证据必须另取。每次写操作后 `worldmem` 回读目标格，
不符就重试（最多 3 次），仍不符则记为 `failed` 并打印诊断，**不要**在返回值上做判断。

### 2. 交互距离是「眼→方块中心」≤ 4.5，不是「脚→方块」

站在路面上（脚 y=69，眼 y=70.62）往 `y=68` 放方块，垂直差就有 2.12；
再算水平 2 格 → `sqrt(2² + 2.12²) = 2.9`；三格开外就到 4.6，**静默失败**。

**做法**：一律用 4.0 做安全阈值；超过就先走近，不要指望"再试一次就好了"。

### 3. 负坐标必须 `math.floor`，`int()` 会往 0 取整

`int(-412.7) == -412`，于是"玩家在第 -413 格"被算成 -412，所有相对偏移全错一位。

### 4. 站在目标列里放方块 = 全部失败（body-block）

服务端认为方块要生成在实体内，整列 5 格一起失败。
**做法**：动手前检查 `px == x`，是就挪到隔壁列；并且**永远站在已铺好的那一侧**。

### 5. z 也要回中线，不然每列缺一条边

站位容差 ±1 格时，玩家停在 `z=271`，`z=270` 那一格正好在自己侧后方 → 服务端拒绝。
症状极具迷惑性：**只有最北一条边一直空着**（`deck@270` + `float@270`）。
**做法**：`if pz != z_center: 回到中线` 再开始铺。

## 二、世界读取

### 6. 未加载区块一律读成空气

`/blockmap` 对没加载的区块返回 AIR。于是「桥被削平了」「这一段全空」这种恐怖结论，
十有八九只是**离玩家太远**。

**做法**：回读前先走到 100 格内；`worldmem.refresh_near()` 必须**校验返回的 box 是否等于请求的 box**，
不符就重试并最终抛错（早期只校验 seq，在新建实例上等于没校验）。

### 7. 异步队列要等，但不要死等

`/dig` 是队列式的（约 1 块 / 0.3 秒，6-tick 冷却）。立刻回读必然读到还没破的方块。
正确姿势是「提交一整批 → 轮询队列进度 `total/index/remaining` → 归零后再回读」。

## 三、材料与工具

### 8. 工具的耐久是隐藏的时间黑洞

石镐 131 耐久，深山一列要削 15~25 格 → **约 6 列废一把**。
不备货的后果是：每 6 列停一次去砍树、合板、合棍、合镐，节奏碎成渣。

**做法**：常备 3 把镐 + 2 把锹；木头留 8 个余量（进沙漠/海边就没树了）。

### 9. `ensure_tools()` 这类"至少有一把"的函数会挡住备货

`if picks > 0: return True` —— 你永远补不到第 2 把。
**做法**：另写 `ensure_pick_count(n)`，明确目标数量；"够用"和"够备"是两个需求。

### 10. 挖土必须用锹，别拿镐硬刨

锹挖泥土/草方块约 0.15 秒；镐子几乎没有加速，还白烧耐久。
`tool_kind(material)` 按方块种类选工具：土→锹、石→镐、木→斧。
**注意**：自动补锹是独立逻辑，只补镐的驱动器会一直拿镐刨土（本项目真发生过）。

### 11. 采集速度差 10 倍的写法差异

同一片地：
```
#mine dirt          → 90 秒 +9 格
#mine grass_block   → 60 秒 +88 格
```
Baritone 对**具体方块 id** 的采集会自己走过去 + 捡掉落；用泛称时它挑得很少。
**做法**：采集命令写英文 id（`grass_block` / `sand` / `stone` / `spruce_log`），并指定 `#mine` 而非手动 `/dig`（后者不捡掉落）。

### 12. 背包满 36/36 时，合成成品取不出来

`crafted 1 x 石镐` 但 `/pack picks = 0`，结果槽一直挂着那张镐。
**做法**：合成前 `ensure_space()`（先丢垃圾：火药/青金石/沙子/玩家头颅/多余圆石），
合成后仍不在背包就用 `move slot=0` 兜底。

### 13. 合成界面会"脏"

连续合成时上一次的结果没取走，下一次配方就匹配失败（`missing-material`）。
**做法**：每次合成都先关界面再开（`craft_clean`），别在同一个界面上连着搓。

## 四、生存与恢复

### 14. Baritone 的 goal 不会因为死亡失效

人死了、复活了，`GoalBlock{...}` 还挂着 —— **一复活就自己往目标走**。
这在旁观者眼里极其明显（"死了还在寻路"）。

**做法**：三处闸门一起上：
1. 血量守卫发现 `alive=false` → **先 `#stop` + 抬键**，再点复活；
2. 守命进程同样先 `#stop` 再复活，然后 `/home`；
3. 驱动器用 `/state` 的 **`last_death` 时间戳**做判据：变了就停手 + `/home` + 跳过本批。
   不要用"距离 > N 格"这种事后判据 —— 会被绕过。

### 15. `/back`、`/home` 这类传送有 3 秒读条，**期间移动就取消**

复活点常在水里，人会持续上下浮动 → `传送已取消——你移动了`。
**做法**：按住潜行 3 秒把浮动定住，再发传送：

```python
set_input('SNEAK', True); sleep(3.0)
chat('/home'); sleep(6.0)
set_input('SNEAK', False)
```

### 16. 复活点 = 床，不是 `/sethome`

`/sethome` 只是插件的传送点，**不改变原版重生点**。
没有有效床时死亡会被扔回世界出生点（本项目那次是海底水腔，回工地要游 500 格）。

**做法**：在工地放一张床**并且不要拆**；`/sethome` 每批更新一次作为传送兜底。
另外：**拆掉床会让重生点失效** —— 这个坑踩过一次，代价是死一次游 8000 格。

### 17. 长途不要走，要传

几百格走路 = 几分钟 + 一路上被怪打死 + 在服务端留下显眼轨迹。
**做法**：`travel()` 里距离 > 40 格就先 `/home`，再 `/back`，都不行才退回 Baritone 走。

## 五、地形

### 18. 水面段要起拱桥，且**不要站在水列上**

- 站在水里 → 游泳状态，Baritone 寻路失效（人会乱走）；
- 水面列没有支撑，`sink_to_deck` 会把人挖到水里。
**做法**：`is_wet(x)` 判定（**往下看 6 格**，水面段的水常在 deck-6 附近，只看 3 格会漏判），
水列一律不作为站位候选；前方水面 ≥2 列就整体交给 `bridge.py`。

### 19. 大海要"先备料再架桥"

在海中央挖不动、也站不住。`water_run >= 12` 时先退回陆地（`x+8`）把料备够
（`需要 ≈ 跨度×5 + 40`），再一次性架过去。

### 20. 沙漠就地取材，别硬找土

地表判定 `surface_kind(x) → sand / dirt / stone / water`：
沙漠里 `#mine sand`（沙子本身就是合法路面材料），森林里挖草方块，山地挖石头。
**选材池**：泥土 / 圆石 / 沙子，背包里哪种多就铺哪种 —— 混铺完全没问题，别为了统一材料停工。

## 六、长跑（通宵）稳定性

### 21. 单个进程再稳也是一个进程

一晚上真正让工程停下的，几乎都是这两件事：**驱动器抛异常退出**、**游戏崩了**。

**做法**：`runner.py` 做守护：
- 读断点文件 `west_end.txt`（每批落盘），子进程退出就重新拉起；
- `/ping` 连续 3 次不通 → 认定游戏挂了 → 跑启动脚本重开并进服；
- 断点连续 2 轮不动 → 点一次「回到游戏」除卡（典型是暂停菜单）。

### 22. 暂停菜单会让一切静默失效

游戏停在「游戏菜单」时，桥还活着、脚本还"成功"，但角色一动不动。
**做法**：帧哈希长时间不变 + 断点不推进 → 点击「回到游戏」按钮的固定坐标。

### 23. 看门狗必须在**启动时回顾日志**

只在启动后跟踪新增行的话，**在你启动之前就已经进服的人你永远不会知道**
（本项目就漏过一次：某玩家退出时才在日志里看到 `XXX 退出了游戏`）。

**做法**：启动时读日志尾部（最近 ~400 KB），用 join/leave 事件重建"当前在线集合"，
命中非白名单就立刻停机；命中后写 `HALT` 旗标，所有子进程每批开头检查它。

### 24. 截图守护要防"静默复制旧帧"

窗口被最小化时 `CopyFromScreen` 拿不到游戏画面，脚本不会报错，只是把上一张复制一遍。
**做法**：每帧算 sha256，连续多帧完全相同就告警。

## 七、给"用 AI 长时间跑工程"的三条

### 25. 判据要用**事件**，不要用**状态差**

"距离 > 80 格"是状态差，会被各种中间态绕过；`last_death` 时间戳是事件，一变就是变了。

### 26. 每一条硬编码的血量/数量门槛，都会在某个时刻变成死锁

`health < 12 拒绝挖矿` 导致 HP 7 时材料永远补不上，整条链原地卡死，还被误报成"连续 3 批施工出问题"。
**做法**：门槛全部参数化（`--min-hp`），并想清楚"低了以后怎么办"（本项目的答案：死了当回血）。

### 27. 别用 sed 批量改 Python

`sed` 出来的 `NameError: name 'verbose' is not defined` 让 `ensure_tools()` 崩了半小时，
驱动器一直以为"补给失败"。**批量替换后必须 `py_compile` + 真跑一次**，编译过 ≠ 能跑。
